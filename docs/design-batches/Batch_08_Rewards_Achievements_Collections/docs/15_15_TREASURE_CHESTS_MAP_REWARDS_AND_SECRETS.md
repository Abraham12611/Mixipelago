# 15 — Map Treasures, Chests and Hidden Rewards

**Batch 8 design status:** proposed · not shipped · values and release targets require implementation review.

## Cross-system ownership
Batch 5 controls map treasure nodes, reveal/eligibility and route prerequisites. Batch 8 controls reward entitlement, visible prize disclosure and ownership. Batch 6 handles any trusted coin grant. An island treasure cannot be generated by an arbitrary client map click.

## Chest types
1. **Fixed chest:** visible published rewards; claim once (recommended initial production behavior).
2. **Choice chest:** player selects one of several disclosed eligible rewards; selection becomes part of claim fingerprint.
3. **Mystery chest:** server selects from approved probability table; optional later feature with published odds and eligibility limitations.
4. **Event chest:** scoped to a published season/event entitlement, never a hidden forced-spend mechanic.

## Interaction flow
Reveal map node → inspect reward preview and claim requirements → click chest → server recomputes eligibility from verified graph facts → creates/dedupes entitlement → settles grant → returns receipt → display opening animation. If player closes modal during animation, reward remains safely owned.

## Secret discovery
Hints may be optional and cosmetics-only. Explorers' skill perks may improve clue visibility but may not access unpublished content or duplicate chest rewards. Hidden chests must be reachable without paid boosters or mandatory social invites.

## Test cases
Two devices click same chest; one award. Claim before reveal rejects. Chest removed after being claimed preserves receipt. Event ended after claim reservation follows published grace policy. Corrupt prize item ID blocks publication. Offline tap can preview chest but must not claim trusted resources.

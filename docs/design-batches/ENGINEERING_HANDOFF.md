# Engineering Handoff and Release Discipline

1. Start with Batch 01 for scope and the initial 72-hour alpha plan.
2. For gameplay, read Batch 02 fixed timestep/collisions, Batch 03 drink ladder/order-priority, and Batch 04 mission rules together.
3. For islands, connect Batch 05 graph nodes to published, proven Batch 04 mission fixtures; do not make draft nodes playable.
4. For economies, Batch 06 specifies a server-owned wallet and ledger. Keep it behind feature gates until authenticated and validated receipts exist.
5. Ship progressively. A document being complete does **not** mean its proposed systems are implemented.
6. Never implement nonfunctional paid upgrade controls or grant trusted coins from client preview values.
7. Engineers open isolated branches and PRs; no engineer self-merges. Owner directs manual interface/gameplay acceptance.
8. Test on desktop and mobile browsers with actual gameplay, network interruptions, and safe recovery.

9. For Batch 08, grant durable achievements only from verified receipts; show claimable versus claimed explicitly; use server-owned entitlements, item catalog and inventory. Batch 06 owns wallet credits and Batch 07 owns XP/skill points. Daily/weekly and randomized rewards remain feature-gated proposals.

10. For Batch 09, customer art and voice are read-only consumers of session events. Preserve scripted alpha orders and oldest-first automatic serving; add dynamic selection, reputation and relationships only through independent OFF-by-default gates and verified backend receipts. VIP and critic pools do not appear in fixed/ranked modes.

11. Batches 10–12 world/story/events are optional and pinned to published editions. No negative wallet effects during offline absence; all durable rewards flow through verified Batch 06/07/08 issuers.
12. Batch 13 owns official ranking verification, standard build and season prize eligibility. Never display local-preview scores as ranked.
13. Batch 14 social work launches block/privacy/report controls before open discovery or collaboration. Async challenges require Batch 13 verified replays; real-time requires a persistent authoritative session service and moderated communication.
14. Batch 15 UI tokens/components must ship with working routes, tests, responsive states and owner-directed manual acceptance. Artwork alone is never a functioning button.

15. Batch 16 art must ship from reviewed original or licensed sources, immutable asset IDs and tested low-end texture budgets. Decorative skins never change rigid-body geometry.
16. Batch 17 audio is a read-only semantic event consumer, with gesture-unlocked Web Audio, bounded polyphony, mute/visual fallback and original music rights.
17. Batch 18 introduces authenticated trusted sessions, domain-owned ledgers, immutable reward receipts, RLS grants and an outbox one feature at a time. Preserve preview-only alpha play.
18. Batch 19 requires authorization tests, replay verification, unique award keys, safe incident gates and independent security review before money or ranked/social claims.
19. Batch 20 optional cosmetics, passes and ads remain OFF; provider-verified receipts, refund/restore, store policies and privacy/age disclosures are prerequisites. Ranked must be normalized.
20. Batch 21 wraps the same deterministic browser core through Capacitor only after web performance/retention; confirm current Apple/Google requirements and owner-approve native device tests/store submission.
